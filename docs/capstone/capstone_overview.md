# 🎓 Capstone：全栈企业智能客服 Agent —— 方案与架构

> 课程毕业大项目。它不教新知识点，而是把前六个 Stage 的能力拧成一个**前后端齐全、能一键部署**的真实产品。做完它，你简历上就有了一个能讲清每一处技术选型、覆盖 Agent 工程师全部核心能力的端到端系统。
>
> 代码：`capstone/`（v2 全栈版）

---

## 一、为什么选「智能客服」作为毕业项目

它**天然需要全部六大能力**，且是企业最高频的 LLM 落地场景：

> 用户说：「我上周买的 10001 这个订单，想退款。」
>
> 系统要：识别这是**退款**意图（路由）→ 查到订单金额（工具）→ 发起退款但**不能自己拍板**，要**人工审批**（HITL）→ 审批通过才真正退款 → 整个过程记住上下文（记忆）→ 这一切通过**网页**交互、能**部署上线**。

## 二、系统架构（全栈）

```
  浏览器 (frontend/index.html, 原生JS聊天界面 + 审批按钮)
        │  POST /api/chat        │  POST /api/approve
        ▼                        ▼
  ┌──────────────────── FastAPI 后端 (backend/api.py) ────────────────────┐
  │                    托管前端 · 会话隔离 · 审批恢复                       │
  └───────────────────────────────┬───────────────────────────────────────┘
                                   ▼
  ┌──────────── 多 Agent 编排图 (backend/graph.py, LangGraph) ────────────┐
  │                                                                        │
  │            ┌──→ policy   (RAG 查政策, backend/kb.py) ──┐               │
  │  triage ───┼──→ order    (订单工具, backend/tools.py) ─┼──→ END        │
  │ (主管路由) ├──→ other     (闲聊) ─────────────────────┘               │
  │            └──→ prepare_refund ─→ ⏸人工审批⏸ ─→ execute_refund ─→ END │
  │                                                                        │
  │  持久化记忆：SqliteSaver(memory.sqlite) 按 session_id 存对话状态        │
  └────────────────────────────────────────────────────────────────────────┘
```

## 四、关键设计取舍

1. **主管路由而非单 Agent 全揽**：`triage` 先用结构化输出判意图，再分发给专精节点。每个节点职责单一、可单独优化、可插护栏——这就是 Supervisor 模式的价值。
2. **退款必须 HITL**：涉及钱的动作绝不让模型自己拍板。用 `interrupt_before` 在执行前冻结，前端弹审批按钮，人点了才恢复执行。这是 Agent 落地企业的安全底线。
3. **记忆持久化到 SQLite**：用 `SqliteSaver` 而非内存，服务重启对话不丢；按 `session_id`(=thread_id) 隔离不同用户。
4. **评测闭环**：`eval/run_eval.py` 把客服质量跑成分数，迭代有据可依，而不是「感觉还行」。
