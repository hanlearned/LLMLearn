# 🎓 Capstone：企业智能客服 Agent —— 方案与架构

> 这是整个课程的毕业项目。它不教新知识点，而是把前六个 Stage 的能力**拧成一个完整系统**。做完它，你简历上就有了一个能讲清每一处技术选型、覆盖 Agent 工程师全部核心能力的端到端项目。
>
> 代码：`capstone/`

---

## 一、为什么选「智能客服」作为毕业项目

因为它**天然需要全部六大能力**，而且是企业里最高频的 LLM 落地场景之一：

> 用户说：「我上周买的东西还没到，能退吗？」
>
> 一个合格的客服 Agent 要自己完成：**查物流**（工具）→ **查退货政策**（RAG）→ 结合**上文记忆**判断 → 必要时**开人工工单**（工具）→ 流式回复用户。

这一句话背后，把 RAG、工具调用、Agent 自主决策、多轮记忆、工程化部署全都串起来了。

## 二、系统架构

```
                         ┌─────────────────────────────────────┐
   用户(session_id) ──▶  │   FastAPI 部署层 (api.py)            │  ← 能力6：流式SSE+会话隔离
                         │   /chat  /chat/stream  /health       │
                         └──────────────────┬──────────────────┘
                                            ▼
                         ┌─────────────────────────────────────┐
                         │   LangGraph 客服 Agent (agent.py)    │  ← 能力4：create_react_agent
                         │   ReAct 循环 + checkpointer 记忆      │  ← 能力5：多轮记忆/轨迹
                         └──────┬───────────┬──────────┬────────┘
                                ▼           ▼          ▼
                       search_policy  get_order_  create_ticket
                       (RAG 检索)      status      (开工单)
                          ▲            (业务工具)   (业务工具)     ← 能力3：工具调用
                          │
                    客服政策知识库(Chroma)                        ← 能力2：RAG
```

## 三、六大能力对照（这就是你的能力证明）

| 能力 | 在本项目的体现 | 出处 Stage |
|------|---------------|-----------|
| 1 LCEL 编排 | 工具内部 `prompt \| llm` 组合、结构化输出 | Stage 1 |
| 2 RAG | `search_policy` 工具：政策知识库检索，答得有据 | Stage 2 |
| 3 工具调用 | `get_order_status` / `create_ticket` 业务工具 | Stage 3 |
| 4 Agent 编排 | `create_react_agent` 自主决定调哪个工具、什么顺序 | Stage 3/4 |
| 5 记忆/可观测 | `checkpointer` 多轮记忆 + 工具调用轨迹打印 | Stage 3/4 |
| 6 部署 | FastAPI + SSE 流式 + `session_id` 会话隔离 | Stage 6 |

> 对照[总纲的能力自检清单](../roadmap.md)：能独立讲清本项目每个模块的「为什么这么选」，就达到了初/中级 Agent 开发工程师水平。

## 四、关键设计取舍

1. **RAG 作为 Agent 的一个工具，而不是独立流程**：政策问答被封装成 `search_policy` 工具，Agent 自己决定「这个问题要不要查政策」。这是复杂 Agent 系统的标准搭法。
2. **业务动作工具化**：查订单、开工单都是工具，Agent 编排它们的调用顺序。
3. **记忆按会话隔离**：用 `session_id` 当 `thread_id`，不同用户互不串台，同一用户多轮有上下文。
4. **温度 0**：客服要稳定、可复现、不能瞎发挥。
