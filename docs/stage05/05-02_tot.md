# 05-02 Tree-of-Thoughts：多路径探索 + 自评估剪枝

> 🎯 **一句话**：ToT（思维树）把 CoT 的「一条路走到黑」升级为「同时探索多条推理路径、自我打分、剪掉差的、深入好的」，用搜索换更高的复杂问题求解能力。

---

## 为什么需要它

CoT 是**单条**推理链：第一步走错，后面全错，且无法回头。对需要试错、规划、有多种解法的问题（数独、24 点、复杂规划），单链很容易一条道走到黑。

ToT 借鉴搜索算法：在每个推理节点**生成多个候选下一步**，对候选**自我评估打分**，**保留最优的几条、剪掉差的**，再继续向下展开——形成一棵「思维树」。本质是用「广度探索 + 评估剪枝」换取在难题上的成功率，代价是多倍的 LLM 调用成本。

---

## 核心用法

ToT 没有官方一行 API，核心是「生成候选 → 评估 → 选择」三步循环。下面用最小代码演示其骨架。

```python
from dotenv import load_dotenv
load_dotenv()

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from common.llm_provider import get_llm

llm = get_llm(temperature=0.8)        # 探索阶段需要多样性，温度调高
judge = get_llm(temperature=0)        # 评估阶段要稳定，温度=0

# 1) 生成候选：让模型对当前局面给出 N 个不同的下一步思路
gen_prompt = ChatPromptTemplate.from_template(
    "问题：{question}\n当前思路：{path}\n请给出一个【不同于以往】的下一步推理，仅一句话。"
)
gen = gen_prompt | llm | StrOutputParser()

# 2) 自评估：让模型给每条候选打分（0~10，越接近答案越高）
eval_prompt = ChatPromptTemplate.from_template(
    "问题：{question}\n候选推理：{candidate}\n"
    "评估这条推理离正确解有多近，只回一个 0~10 的整数。"
)
evaluate = eval_prompt | judge | StrOutputParser()


def tot_search(question, beam=3, depth=2):
    paths = [""]                       # 初始只有空路径（树根）
    for _ in range(depth):             # 逐层加深
        candidates = []
        for p in paths:
            for _ in range(beam):      # 每条路径扩展 beam 个候选
                step = gen.invoke({"question": question, "path": p})
                score = int("".join(filter(str.isdigit, evaluate.invoke(
                    {"question": question, "candidate": step})) or "0"))
                candidates.append((p + " -> " + step, score))
        # 剪枝：按分数排序，只保留 top-beam 条继续深入
        candidates.sort(key=lambda x: x[1], reverse=True)
        paths = [c[0] for c in candidates[:beam]]
    return paths[0]


print(tot_search("用 4、9、10、13 凑出 24（可加减乘除）"))
```

**逐块讲解：**
- **生成（gen）**：用较高 `temperature` 让模型每次给出**不同**的下一步，制造分叉——这是「树」的宽度来源。
- **评估（evaluate）**：用 `temperature=0` 的评判模型给每个候选打分，估计它「离答案有多近」。这是 ToT 区别于 CoT 的灵魂：**模型给自己的中间步骤当裁判**。
- **剪枝（top-beam）**：每层只保留分数最高的 `beam` 条路径继续深入，差的直接砍掉，避免组合爆炸。
- **逐层加深（depth）**：循环 depth 次，相当于在思维树上做 beam search。

---

## 关键原理 / 实践要点

1. **ToT vs CoT 的本质区别**：CoT 是**一条链**（线性、不可回退）；ToT 是**一棵树 + 搜索**（多分支、可评估、可剪枝、可回溯）。ToT 在难题上更强，但调用次数是 CoT 的数倍到数十倍。
2. **三要素**：思维生成器（给候选）、状态评估器（打分）、搜索算法（BFS/DFS/beam search 决定怎么遍历）。缺一不可。
3. **成本权衡**：`beam × depth` 直接决定 LLM 调用量。beam=3、depth=3 就已是约 30+ 次调用。**只在 CoT 明显不够、问题确实需要试错规划时才用 ToT**，否则纯属烧钱。
4. **评估器是瓶颈**：自评估若不准，剪枝会把正确路径砍掉。可让评估器也输出理由、或用多次评估投票提升可靠性。
5. **工程现实**：生产中很少直接上完整 ToT，更多用其思想的轻量版——如「生成 3 个方案 → 选最优」（深度=1 的 ToT），性价比更高。

## 面试怎么考

**Q：Tree-of-Thoughts 和 Chain-of-Thought 的核心区别？**
A：CoT 是单条线性推理链，错了无法回退；ToT 把推理建模成一棵树，在每个节点生成多个候选下一步，用模型自评估打分、剪掉差的、深入好的，相当于在思维空间做搜索（BFS/DFS/beam search）。ToT 能解 CoT 解不了的需试错/规划类难题，但调用成本高数倍。

**Q：ToT 由哪几部分组成？成本怎么控制？**
A：三要素——思维生成器、状态评估器、搜索算法。成本主要由 beam 宽度 × 搜索深度决定，调用量呈乘积增长。控制手段：限制 beam/depth、只对真正需要的难题启用、或退化为「生成多方案选最优」的轻量版。

**Q：ToT 最大的风险点是什么？**
A：自评估器的准确性。评估不准会剪掉正确路径、保留错误路径，让搜索方向跑偏。缓解：让评估输出理由、多次评估投票、或引入可验证的客观信号（如代码能否运行）。
