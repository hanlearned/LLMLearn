# 05-01 Chain-of-Thought：让模型「想清楚再答」

> 🎯 **一句话**：CoT（思维链）通过让模型把推理步骤显式写出来再给结论，把「一步到位猜答案」变成「分步推导」，显著提升数学、逻辑、多跳推理类任务的正确率。

---

## 为什么需要它

大模型本质是「逐 token 预测」。要它对一道需要多步推理的题直接吐出最终答案，相当于逼它在一个 token 内完成全部心算——很容易错。

CoT 的核心洞察：**给模型更多「思考的 token 空间」，让中间推理过程显式展开**。当模型先写出「第一步…第二步…」，每一步都建立在前一步的文本之上，错误更容易被自我纠正，最终答案的正确率随之上升。这也是 o1、DeepSeek-R1 等「推理模型」的底层思想。

---

## 核心用法

### 1. Zero-shot CoT：一句「让我们一步步想」

```python
from dotenv import load_dotenv
load_dotenv()

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from common.llm_provider import get_llm

llm = get_llm(temperature=0)

# 关键就在这句「请一步步推理」
cot_prompt = ChatPromptTemplate.from_messages([
    ("system", "你是严谨的数学助手。请一步步推理后再给出最终答案。"),
    ("human", "{question}"),
])

chain = cot_prompt | llm | StrOutputParser()

q = "一个班 35 人，男生比女生多 5 人，男生有多少人？"
print(chain.invoke({"question": q}))
```

**本质在干什么？** 仅仅在 system 里加一句「一步步推理」，就触发模型先输出推导过程（设女生 x，男生 x+5，2x+5=35…）再给结论。这就是 zero-shot CoT——不给任何示例，只靠一句魔法指令。代价是输出变长、变慢。

### 2. Few-shot CoT：用示例「示范」推理格式

```python
from langchain_core.prompts import ChatPromptTemplate

# 在 prompt 里塞进 1~2 个「带推理过程」的范例
fewshot_prompt = ChatPromptTemplate.from_messages([
    ("system", "参照示例的推理方式解题。"),
    ("human", "停车场有 3 排车，每排 4 辆，开走 2 辆，还剩几辆？"),
    ("ai", "推理：3×4=12 辆，开走 2 辆，12−2=10。答案：10 辆。"),
    ("human", "{question}"),
])

chain = fewshot_prompt | llm | StrOutputParser()
print(chain.invoke({"question": "篮子里 5 个苹果，拿走 2 个又放回 4 个，现在几个？"}))
```

**本质在干什么？** few-shot CoT 不是用指令、而是用**带推理过程的示例**告诉模型「该怎么想」。模型会模仿示例的推理粒度与输出格式。它对格式控制更强、更稳定，适合需要固定推理风格的场景；代价是 prompt 更长、token 成本更高。

### 3. CoT 与结构化输出冲突时：分离「思考」与「结果」

```python
# 错误做法：既要 JSON 又要它一步步想 → 推理文本会污染 JSON
# 正确做法：让它先想，再把结论包进固定标记，事后提取
cot_then_answer = ChatPromptTemplate.from_messages([
    ("system",
     "先在 <think> 标签内逐步推理，然后在 <answer> 标签内只写最终数字。"),
    ("human", "{question}"),
])
text = (cot_then_answer | llm | StrOutputParser()).invoke({"question": q})

import re
answer = re.search(r"<answer>(.*?)</answer>", text, re.S)
print("最终答案：", answer.group(1).strip() if answer else text)
```

**本质在干什么？** CoT 要求模型「多说话」，而结构化输出（如严格 JSON）要求它「只说结果」——两者天然矛盾。解法是**用标签把推理和结论物理隔开**：让模型在 `<think>` 里自由推理，在 `<answer>` 里给纯结果，再用正则/解析器只取 `<answer>`。

---

## 关键原理 / 实践要点

1. **为什么 CoT 有效**：自回归模型每一步预测都依赖前文。把推理过程写出来，相当于给模型搭了「思考脚手架」，让难题被拆成一连串简单的下一 token 预测，错误率下降。
2. **zero-shot vs few-shot**：zero-shot 省 token、上手快，但格式不可控；few-shot 用示例锁死推理风格，更稳但更贵。生产里常先用 zero-shot，效果不稳再升级 few-shot。
3. **对结构化输出的副作用**：直接对 JSON 输出加 CoT，会让推理文本混进 JSON 导致解析失败。两种解法：① 标签隔离后提取；② 先调一次拿推理结论，再调一次只做结构化（two-pass）。
4. **推理模型的特殊性**：o1 / DeepSeek-R1 这类模型已内置 CoT，**不要再手动加「一步步想」**，反而可能干扰其内部推理；它们的「思考过程」由模型自行管理。
5. **不是万能**：对简单事实问答、纯检索任务，CoT 只增加延迟和成本，不提升质量，要按任务类型决定是否启用。

## 面试怎么考

**Q：Chain-of-Thought 为什么能提升推理准确率？**
A：大模型是自回归逐 token 生成的，直接给最终答案等于在极小空间里完成全部推理，易错。CoT 让模型把中间步骤显式写出，每一步都基于前文，相当于把难题拆成一连串简单的 next-token 预测，并提供自我纠错机会，从而提升数学/逻辑/多跳推理任务的正确率。

**Q：zero-shot CoT 和 few-shot CoT 区别？**
A：zero-shot 靠一句「让我们一步步思考」触发推理，省 token、格式不可控；few-shot 在 prompt 里给出带推理过程的范例，模型模仿其推理粒度与格式，更稳定但 token 成本更高。

**Q：要 JSON 结构化输出又想用 CoT，怎么办？**
A：两者矛盾（CoT 要多说、结构化要只说结果）。可用标签把推理与结论隔离（`<think>`/`<answer>`）后提取，或采用 two-pass：先推理拿结论，再单独做一次结构化输出。另外，对已内置推理的模型（o1/R1）不应再手动加 CoT 指令。
