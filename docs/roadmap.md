# 🎯 总纲：从 0 到 Agent 开发工程师

> 这份文档是整个仓库的「地图」。它回答三个问题：**为什么这样学**、**学完能干什么**、**怎么验证自己到了**。
> 读完它，再按左侧目录逐篇推进。

---

## 一、目标岗位画像：什么是「Agent 开发工程师」

不是「会调 OpenAI API」，也不是「会写 Prompt」。2025+ 招聘 JD 里真正在招的是这样一个人：

> 能把一个**模糊的业务需求**，拆解成**多个可被大模型驱动的步骤**，让模型**自主决定调用哪些工具 / 检索哪些知识 / 何时向人求助**，最终产出**可靠、可观测、可上线**的系统。

拆开看，是六块硬能力：

| # | 能力 | 一句话标准 | 对应 Stage |
|---|------|-----------|-----------|
| 1 | **LLM 编排基础** | 能用 LCEL 把 Prompt/模型/解析/分支组合成任意链路 | Stage 1 |
| 2 | **RAG 全链路** | 能从一堆原始文档建出「检索得准、答得有据」的问答系统，并能量化它的好坏 | Stage 2 |
| 3 | **工具调用 / Agent** | 能给模型装上工具，让它自己决定调用顺序，并处理失败重试 | Stage 3 |
| 4 | **多 Agent 编排** | 能用 LangGraph 把多个角色编成有状态、可持久化、可人工介入的工作流 | Stage 4 |
| 5 | **评测 / 可观测** | 能说清「这个 Agent 为什么这次答错了」，并用指标驱动迭代 | 贯穿 + Stage 5 |
| 6 | **工程化上线** | 能把上面任何一个做成带流式、带缓存、能容器化部署的服务 | Stage 6 |

**本课程的设计原则**：能力 3/4（Agent）是核心，能力 5（评测）从 Stage 2 就开始渗透而不是放到最后，能力 6（工程化）从第一个项目就带一层 API，而不是攒到结尾。

## 二、为什么是这条路线（设计取舍）

这套课程相比「网上随便一个 LangChain 教程」做了几个**刻意的取舍**，理解它们能帮你少走弯路：

### 1. Agent 一律用 LangGraph 实现，`AgentExecutor` 只讲不依赖
LangChain 老的 `AgentExecutor` / `initialize_agent` 已进入**软弃用**，官方明确引导用 LangGraph 重写。本课程 Stage 3 会讲清 `AgentExecutor` 的执行循环原理（面试要考、看老代码要懂），但**所有实战代码都用 LangGraph 的 `create_react_agent` / `StateGraph`** —— 学一套不会马上过时的东西。

### 2. 评测（Eval）不是单独一个阶段，而是一条暗线
很多人 RAG / Agent 做完只会「肉眼看答得对不对」。工程师和爱好者的分水岭就在这。所以：
- Stage 2 一上来就建**评测集**，用「检索命中率 / 答案忠实度」量化 RAG。
- Stage 3/4 的 Agent 都要能打印**完整执行轨迹（trace）**，定位它在哪一步选错了工具。
- Stage 5 系统化讲 LLM-as-a-Judge 和 A/B 评测平台。

### 3. 每个项目都带「方案 → 实现 → 代码 → 复盘」四件套
光有能跑的代码不够。每个实战项目的文档都包含：**需求与方案设计**（为什么这么架构）、**关键实现讲解**（核心难点怎么解决）、**完整代码**、**复盘与面试问法**（这个项目在面试里会被怎么追问）。

### 4. 工程化前置
从项目 2 开始，每个项目都给一个最小 FastAPI 入口，让你习惯「写的东西是个服务，不是个脚本」。

## 三、六个 Stage 全景

```
Stage 1  LLM 编排基础      ── LCEL / Prompt / 结构化输出      [已完成]
   │
Stage 2  RAG 全链路        ── 切分→向量→检索→重排→评测        项目2 知识库QA · 项目3 GraphRAG
   │
Stage 3  工具与 Agent      ── Tool Calling / ReAct / Memory   项目4 数据分析 Agent
   │
Stage 4  LangGraph 编排    ── StateGraph / 持久化 / HITL      项目5 内容创作 · 项目6 招聘助手(MCP)
   │
Stage 5  评测与 PromptOps  ── CoT/ToT / LLM-as-Judge / A-B     项目7 Prompt A/B 平台
   │
Stage 6  工程化部署        ── FastAPI/SSE / 缓存 / Docker     项目8 企业 API 平台
   │
Capstone  毕业综合项目     ── RAG+Agent+Tools+Memory+部署 一体  「企业智能客服 Agent」
```

| Stage | 你会从「不会」变成「会」的具体事 |
|-------|-------------------------------|
| **1** | 能把任意「输入→模型→结构化输出」需求用 `prompt \| llm \| parser` 拼出来，并处理流式与并行 |
| **2** | 给你一个公司的几百页 PDF/Markdown，你能在一天内建出一个答得准、引得到原文、能评分的问答系统 |
| **3** | 给模型装上「查数据库 / 算数 / 调 API」的手，让它自己决定先做什么后做什么，并能看懂它的思考轨迹 |
| **4** | 把「写作 → 审稿 → 配图」这种多角色协作，编成一张有状态、断点能续、关键步骤能让人审批的图 |
| **5** | 不再靠感觉调 Prompt：能搭一套「同一批问题、两个 Prompt、自动打分对比」的评测流程 |
| **6** | 把上面任何一个 Agent 包成带流式输出、带缓存、能 `docker run` 起来的 HTTP 服务 |
| **Capstone** | 独立完成一个面试可直接拿出手、覆盖全部六大能力的端到端 Agent 系统 |

## 五、能力自检清单（学完逐条打勾，就是一份能力证明）

> 建议把这份清单贴到 `AGENT.md` 顶部，每完成一项打勾。**全部打勾 = 达到初/中级 Agent 开发工程师水平。**

**Stage 1 · 编排基础**
- [ ] 能解释 `Runnable` 协议，以及 `|` 背后是 `RunnableSequence`
- [ ] 能用 `RunnableParallel` / `RunnablePassthrough` 构造分支与透传
- [ ] 能用 `PydanticOutputParser` 拿到强校验的结构化对象，并处理解析失败

**Stage 2 · RAG**
- [ ] 能说清 chunk_size / overlap 如何影响召回，并据此调参
- [ ] 能解释为什么需要 Re-rank，CrossEncoder 和向量检索的区别
- [ ] 能用一个评测集量化「换了切分策略后召回率涨了多少」
- [ ] 能给 RAG 答案附上**出处引用**（防幻觉的工程手段）

**Stage 3 · Agent**
- [ ] 能用 `@tool` 定义带类型校验的工具，并解释模型是「怎么知道」要调它的
- [ ] 能手写一个 ReAct 循环（不靠框架），讲清 Thought/Action/Observation
- [ ] 能给 Agent 加记忆，并解释 Buffer / Summary 记忆的取舍
- [ ] 能读懂 Agent 的执行轨迹，定位「它为什么调错了工具」

**Stage 4 · LangGraph**
- [ ] 能用 `StateGraph` 定义状态、节点、条件边
- [ ] 能用 checkpointer 做持久化，实现「同一会话断点续聊」
- [ ] 能加一个 Human-in-the-loop 审批节点
- [ ] 能实现 Supervisor 模式调度多个子 Agent

**Stage 5/6 · 评测与上线**
- [ ] 能用 LLM-as-a-Judge 给两版 Prompt 的输出自动打分
- [ ] 能把一个 Agent 用 FastAPI + SSE 暴露成流式接口
- [ ] 能给系统加缓存，并写出 Dockerfile 一键起服务

**Capstone**
- [ ] 独立交付一个融合 RAG + 工具 + 多 Agent + 记忆 + 部署的系统，并能在面试中讲清每个技术选型

## 六、怎么用这个仓库学（节奏建议）

1. **不要先全读文档**。每个知识点：读文档 → 跑对应 `stageXX_*/NN_xxx.py` → 改一处看效果。
2. **项目优先**。基础够用就冲项目；项目里遇到不懂的点再回头查对应文档。
3. **保持「能跑」**。先 `pip install -r requirements.txt`，在根目录建好 `.env`（见 `.env.example`，填一个 Key 即可）。
4. **对照自检清单**。每过一个 Stage，回到第五节打勾；不敢打勾的，就是没真正掌握。

> 下一步 👉 如果 Stage 1 已经跟完，直接进入 [Stage 2 · Document Loaders](stage02/02-01_document_loaders.md)。
